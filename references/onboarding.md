# 首次使用引导

用户第一次使用时，主动问清楚：要不要推送、推到哪里、要不要每天自动检索，以及（没有 Python 时）要不要安装。问完帮用户配好，并记录下来，以后不再重复问。

## 什么时候引导

- 运行 `radar status`，输出 `"onboarded": false` 时，在本次检索**之前**引导。
- 用户说「重新设置」「改一下推送」「换个时间」「不要推送了」时，只引导相关的部分；要全部重来时先运行 `radar onboard reset`。
- **不要引导**的情况：定时任务等无人值守的运行；用户明确说「先别问，直接查」（此时先检索，报告交付后再问一次，用户仍不需要就记为跳过）。
- 没有 Python、用户选择简易模式时，见文末「简易模式下的引导」。

## 第一步：一次问完

把下面的问题**合并成一条消息**提出。当前 Agent 有选择题工具（例如 AskUserQuestion）就用它，没有就用带编号的文字选项，让用户回复编号即可。每个问题都给出默认选项，用户只回复「默认」也能继续。

**问题 1：Python**（只在第 0 步找不到 Python 时问）

> 你的电脑上没有找到 Python，完整功能需要它（一次安装，免费）。
> 1. 现在安装（推荐）：我告诉你一条命令，装好后继续
> 2. 先不装，用简易模式：只靠联网搜索，遗漏会明显增多，也不能自动推送

**问题 2：推送**（可多选）

> 找到新的招标公告时，要推送到哪里？
> 1. 不推送，我在这里看报告就行（默认）
> 2. 钉钉群
> 3. 企业微信群
> 4. 飞书群
> 5. 邮箱
> 6. 微信（通过 Server酱）

选了任一推送渠道时，再问一句：

> 平时你让我手动查的时候，也要推送吗？
> 1. 不用，只有每天定时检索时才推送（默认）
> 2. 要，每次查完都推送

**问题 3：定时**

> 要不要每天自动检索一次，只把新增公告和快截止的项目推送给你？
> 1. 不需要，我想查的时候再叫你（默认）
> 2. 需要，每天早上 8:00
> 3. 需要，只在工作日早上 8:00
> 4. 需要，换个时间：____

用户选了定时，再补问一句**方式**（只有一种可用时直接用，不要问）：

> A. 由我（Agent）每天定时运行：每条公告都会读原文核实，准确度高，但会消耗模型额度，并且需要这个 Agent 软件保持运行。
> B. 由电脑系统定时运行：不消耗额度，但只做规则初筛，推送里会注明「未经逐条核实」；需要电脑开着。

当前 Agent 平台没有定时任务功能时只能选 B；没有推送渠道时，B 方式跑完也只会把报告存在本地，要提醒用户。

## 第二步：按回答配置

### 推送渠道

对每个选中的渠道：

1. 添加渠道：

   | 渠道 | 命令 |
   |---|---|
   | 钉钉 | `radar channel add --type dingtalk --with-sign`（机器人选了「自定义关键词」而不是「加签」时去掉 `--with-sign`） |
   | 企业微信 | `radar channel add --type wecom` |
   | 飞书 | `radar channel add --type feishu`（开启了签名校验时加 `--with-sign`） |
   | 邮箱 | `radar channel add --type email --provider qq --smtp-user 发件邮箱 --to 收件邮箱`（`--provider` 可选 qq、163、126、aliyun、exmail、outlook、gmail） |
   | 微信 | `radar channel add --type serverchan` |

2. 告诉用户怎么拿到密钥（只说用户选中的渠道）：

   - **钉钉**：群设置 → 机器人 → 添加机器人 → 自定义 → 安全设置勾选「加签」（推荐，复制「SEC」开头的密钥），或勾选「自定义关键词」并填写「招标」→ 完成后复制 Webhook 地址。
   - **企业微信**：打开群聊 → 右上角「…」→ 群机器人 → 添加 → 新创建一个机器人 → 复制 Webhook 地址。
   - **飞书**：群设置 → 群机器人 → 添加机器人 → 自定义机器人 → 复制 Webhook 地址；如开启「签名校验」，同时复制签名密钥。
   - **邮箱**：在邮箱网页版的设置里开启 SMTP 服务，生成「授权码」（不是登录密码）。QQ 邮箱：设置 → 账号 → POP3/IMAP/SMTP 服务 → 开启 → 生成授权码。
   - **微信（Server酱）**：打开 sct.ftqq.com，用微信扫码登录，复制 SendKey；再关注提示的公众号，消息会推送到微信。

3. 录入密钥。`channel add` 的输出 `next` 里列出了需要录入的名称。给用户两种方式，**推荐第一种**：

   - **自己录入（推荐，密钥不经过对话）**：请用户在自己的终端里运行 `radar secret set 名称`（把 `radar` 换成第 0 步确定的完整命令），按提示粘贴，输入内容不会显示。Claude Code 用户可以在输入框里以 `!` 开头直接运行。
   - **发给你代为录入（方便）**：用户把密钥发在对话里，你用 `radar secret set 名称 --stdin` 从标准输入写入。录入前提醒用户：密钥会留在对话记录里，以后可在机器人设置里重新生成。录入后**不要复述密钥**，也不要写进报告或任何文件。

4. 发测试消息：`radar channel test --name 渠道名`，请用户确认收到。失败时按错误信息排查（常见：Webhook 复制不完整、加签选项和命令不一致、钉钉关键词没包含「招标」、邮箱用了登录密码而不是授权码）。

### 定时

- **A. Agent 定时任务**：用当前平台的定时任务功能创建每日任务，提示词用 [push-and-schedule.md](push-and-schedule.md) 里的模板，时间按用户的选择。不会创建或平台不支持时，把提示词和操作步骤告诉用户，请用户自己在平台界面里创建。
- **B. 系统定时任务**：运行 `radar schedule install --time 08:00`（只在工作日加 `--weekdays`）。命令会直接调用当前的 Python，密钥从本机读取，不依赖终端环境。输出里有 `note`（例如电脑时区不是北京时间）时要转告用户。用 `radar schedule status` 确认、`radar schedule remove` 删除。

### 记录结果

全部配置完后记录引导结果，这样以后就不会再问：

```bash
radar onboard done --python ok --push dingtalk,email --schedule system --schedule-time 08:00
```

- `--python`：`ok`（本来就有）、`installed`（这次装的）
- `--push`：选中的渠道类型，逗号分隔；不推送填 `none`
- `--schedule`：`none`、`agent`、`system`
- `--push-after-search`：手动查询后是否也推送，`yes` 或 `no`
- 用户全部跳过时：`radar onboard done --skip`

## 第三步：确认

用三五行告诉用户配置结果，以及以后怎么改。例如：

> 已设置好：
> - 推送：钉钉群（测试消息已收到）
> - 定时：工作日每天 8:00 由系统自动检索，只推送新增公告和截止前 3 天、1 天的提醒
> - 以后想改，直接跟我说「改一下推送」或「不要定时了」即可

然后继续执行用户这次真正的请求（例如检索近 30 天的公告）。如果用户开启了推送，第一份报告检索完成后问一句是否现在就推送一次。

## 简易模式下的引导

没有 Python 时脚本都用不了，引导范围缩小：

- 不问推送渠道：简易模式不能自动推送，直接说明。
- 定时只能用 Agent 平台的定时任务，并在提示词中写明「按 references/no-python.md 的简易模式执行」。
- 无法用 `radar onboard done` 记录结果。平台有记忆功能时记下用户的选择；没有就在下次使用时简短确认一次。
- 每次都提醒一句：装好 Python 后可以获得完整功能（官方接口、法院官网扫描、自动推送）。
